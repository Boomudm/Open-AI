ข้อ 4. การตรวจรับ

  1. เกณฑ์บังคับ: AT-01 ถึง AT-05 ตามเช็คลิสต์ NEOCHAT-CHECKLIST-2026-001 / หมวดคุณภาพของชุดส่งมอบ — เป็นเกณฑ์เชิงวัตถุวิสัยที่ทำซ้ำได้
  2. หน้าต่างตรวจรับ: 3 วันทำการ นับจากวันพร้อมตรวจรับ (ปฏิทินประเทศไทย เว้นแต่ตกลงเป็นลายลักษณ์อักษรเป็นอย่างอื่น)
  3. ปฏิเสธที่ชอบด้วยเงื่อนไข: ต้องเป็นลายลักษณ์อักษรภายในหน้าต่าง และระบุขั้นตอนทำซ้ำ สภาพแวดล้อม ผลจริง และเหตุที่อยู่ในขอบเขตส่งมอบ
  4. Deemed acceptance: หากครบหน้าต่างโดยไม่มีปฏิเสธที่ชอบด้วยเงื่อนไข ให้ถือว่ารับมอบโดยสมบูรณ์ แม้ยังไม่ลงนามหน้านี้
  5. Deemed use: หากผู้ว่าจ้างนำไปใช้จริง/production ให้ถือว่ารับมอบส่วนที่นำไปใช้นั้นแล้ว
  6. รอบแก้ไข: ผู้ส่งมอบมีสิทธิ์แก้ defect ที่ชอบด้วยเงื่อนไขได้ หนึ่งรอบ ตามรายการปฏิเสธเดิม — ไม่เปิดประเด็นใหม่ในรอบนั้น

หน้าถัดไป: การรับประกัน ความรับผิด และข้อสงวนสิทธิ์สำคัญของผู้ส่งมอบ

ข้อ 6. ข้อยกเว้นและการจำกัดความรับผิด

  1. ผู้ส่งมอบไม่รับผิดโดยลำพังต่อ: LLM gateway/โควตา, เครือข่าย/TLS/infra ของผู้ว่าจ้าง, คุณภาพเอกสารโรงงาน, การตั้งค่า production ที่ไม่ harden, ของนอกขอบเขต/carve-out
  2. คำตอบ AI เป็น decision-support — ผู้ใช้ต้องตรวจ citation ก่อนปฏิบัติ โดยเฉพาะงานความปลอดภัย/เครื่องจักร/LOTO ผู้ส่งมอบไม่รับผิดต่อผลตัดสินใจที่อาศัยคำตอบระบบ
  3. ภายใต้ขอบเขตที่กฎหมายอนุญาต: ตัดความเสียหายทางอ้อม สืบเนื่อง พิเศษ ขาดกำไร หยุดผลิต สูญเสียข้อมูล/ชื่อเสียง/โอกาส
  4. เนื่องจากเป็นงานในฐานะพนักงานและไม่มีค่าจ้างแยก ความรับผิดของผู้ส่งมอบจำกัดเท่าที่ความสัมพันธ์นายจ้าง–ลูกจ้างและกฎหมายกำหนด — ไม่ใช้เพดานเป็นจำนวนเงิน
  5. เหตุสุดวิสัยและบริการภายนอกที่ระบบพึ่งพาอยู่นอกความรับผิดของผู้ส่งมอบ

ข้อ 7. ทรัพย์สินทางปัญญา และสิทธิที่ผู้ส่งมอบสงวนไว้ / ได้รับอนุญาต

หลักการคู่ขนาน: หน่วยงานรับมอบได้ระบบ Neo Chat ที่ส่งมอบตามจุดอ้างอิงเพื่อใช้งานภายในองค์กร พร้อมกันนั้น ผู้ส่งมอบสงวนและได้รับอนุญาตอย่างชัดเจนซึ่งสิทธิในความรู้ ทักษะ แนวคิดทั่วไป และการนำไปใช้ใหม่ตามข้อนี้ — เพื่อไม่ให้การรับมอบถูกตีความว่าตัดสิทธิทางวิชาชีพของผู้ส่งมอบ

7.1 สิ่งที่หน่วยงานรับมอบได้รับ

  1. สิทธิใช้ ครอบครอง และดูแลระบบ Neo Chat v1.0.0 ที่ส่งมอบ (รวมซอร์ส ณ จุดอ้างอิง) เพื่อวัตถุประสงค์ภายในองค์กร ตาม LICENSE ของโครงการและระเบียบหน่วยงาน
  2. ข้อมูลโรงงาน ความลับองค์กร credentials หลังโอน และเอกสารภายในที่นำเข้า ยังคงเป็นของผู้ว่าจ้าง

7.2 สิทธิที่ผู้ส่งมอบสงวนไว้และผู้ว่าจ้างอนุญาตโดยชัดแจ้ง (สาระสำคัญ)

โดยการลงนาม ผู้ว่าจ้างรับทราบและอนุญาต/ไม่คัดค้าน ให้ผู้ส่งมอบมีสิทธิต่อไปนี้ตลอดไป โดยไม่ต้องขออนุญาตเพิ่ม และโดยไม่คิดค่าตอบแทนเพิ่ม:

  1. ความรู้ ทักษะ และ know-how ทั่วไป — รวมเทคนิค RAG, สถาปัตยกรรมระบบ, แบบแผนการออกแบบ, วิธีทดสอบ, แนวปฏิบัติ DevOps/MLOps และทักษะวิชาชีพที่ได้จากการทำงาน ถือเป็นทุนวิชาชีพส่วนบุคคลของผู้ส่งมอบ
  2. สิทธิ rebuild / สร้างใหม่จากศูนย์ — ผู้ส่งมอบมีสิทธิออกแบบ พัฒนา และส่งมอบระบบที่มีหน้าที่คล้ายคลึงหรือแข่งขันได้ สำหรับนายจ้างรายอื่น ลูกค้า งานประกวด งานแข่งขัน หรือโครงการส่วนตัว โดยไม่คัดลอกซอร์สโค้ดเฉพาะของ Neo Chat และไม่ใช้ข้อมูลลับ/เอกสารโรงงานของผู้ว่าจ้าง
  3. สิทธิใช้แนวคิดและคอนเซ็ปต์ — แนวคิด “ผู้ช่วยถาม-ตอบเอกสารโรงงานแบบ on-prem ที่อ้างอิงแหล่งที่มา” รวมรูปแบบผลิตภัณฑ์ โครงหน้าจอระดับแนวคิด และสถาปัตยกรรมระดับสูง นำไปเสนอในพอร์ตโฟลิโอ งานแข่ง งานสัมภาษณ์ หรือผลิตภัณฑ์ใหม่ได้
  4. สิทธิพอร์ตโฟลิโอ / นำเสนอผลงาน — อธิบายบทบาท ขอบเขตงาน สแต็กเทคโนโลยี แผนภาพสถาปัตยกรรมที่ไม่มีข้อมูลลับ และภาพหน้าจอที่ปิดบังข้อมูลโรงงาน/ข้อมูลส่วนบุคคล ได้ในเรซูเม่ เว็บส่วนตัว สัมภาษณ์ งานประกวด และสื่อวิชาชีพ
  5. สิทธิแสดงความเป็นผู้สร้าง (authorship credit) — อ้างอิงได้ว่าเป็นผู้พัฒนาหลัก/ผู้ส่งมอบ Neo Chat v1.0.0 ในบริบทวิชาชีพ โดยไม่เปิดเผยความลับองค์กร
  6. ทรัพย์สินที่มีอยู่ก่อน / เครื่องมือส่วนตัว — โค้ด ไลบรารี สคริปต์ โน้ต หรือเครื่องมือที่ผู้ส่งมอบมีอยู่ก่อน หรือสร้างขึ้นนอกขอบเขตงานเฉพาะของหน่วยงาน และไม่ได้ฝังความลับของผู้ว่าจ้าง ยังเป็นของผู้ส่งมอบ
  7. ไม่สร้างข้อห้ามแข่งขันจากเอกสารนี้ — การลงนามรับมอบไม่ถือเป็นสัญญาห้ามประกอบอาชีพ ห้ามทำงานแข่ง หรือห้ามพัฒนาผลิตภัณฑ์คล้ายกัน เกินกว่าที่กฎหมายหรือสัญญาจ้างงานฉบับอื่น (ถ้ามี) กำหนดไว้แล้วโดยชัดเจน
  8. งาน open-source / งานสาธารณะในอนาคต — ผู้ส่งมอบอาจเผยแพร่เฟรมเวิร์กหรือตัวอย่างทั่วไปที่สอนแนวคิดคล้ายกันได้ หากไม่เปิดเผยซอร์สเฉพาะของ Neo Chat ที่เป็นความลับ และไม่เปิดเผยข้อมูลโรงงาน

7.3 สิ่งที่ผู้ส่งมอบตกลงไม่ทำ

  • ไม่นำข้อมูลเอกสารโรงงาน ความลับ credentials หรือข้อมูลส่วนบุคคลของผู้ว่าจ้างไปใช้ภายนอก
  • ไม่เผยแพร่ซอร์สโค้ดเฉพาะของ Neo Chat ที่หน่วยงานถือเป็นความลับ โดยไม่ได้รับอนุญาตเป็นลายลักษณ์อักษร (เว้นแต่หน่วยงานทำให้เป็นสาธารณะเอง)
  • ไม่แอบอ้างว่าหน่วยงานรับรองผลิตภัณฑ์ใหม่ที่ผู้ส่งมอบสร้างภายหลัง
