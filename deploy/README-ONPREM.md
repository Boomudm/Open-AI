# Neo Chat — On-Premise Factory Deployment Guide

Deploy Neo Chat entirely on your factory LAN with **no cloud dependency**. This kit packages PostgreSQL, Redis, Qdrant, MinIO, Ollama (local LLM), API, Celery workers, Next.js web UI, and an Nginx reverse proxy with **SSE streaming support** for chat token delivery.

---

## What you get

| Service | Purpose | Data persisted |
|---------|---------|----------------|
| **nginx** | Single entry point (`http://spark.lan`) | — |
| **web** | Next.js operator UI | — |
| **api** | FastAPI backend | `deploy/data/*` bind mounts |
| **celery_worker** | Document ingest, embeddings, OCR | same bind mounts |
| **celery_beat** | Scheduled reports / tagging | — |
| **postgres** | Users, machines, repairs, inventory | Docker volume `spark_onprem_postgres_data` |
| **redis** | Celery broker + session cache | Docker volume `spark_onprem_redis_data` |
| **qdrant** | Vector search (RAG) | Docker volume `spark_onprem_qdrant_data` |
| **minio** | S3-compatible document storage | Docker volume `spark_onprem_minio_data` |
| **ollama** | On-box LLM (Thai chat) | Docker volume `spark_onprem_ollama_data` |

## Quick start (IT admin)

```bash
# 1. Clone the repo on the factory server
git clone https://github.com/CPF-Chula-CEDT-2026/spark.git
cd spark

# 2. One-click deploy (creates deploy/.env, generates secrets, builds, starts)
chmod +x deploy/setup_onprem.sh
./deploy/setup_onprem.sh --seed --pull-models

# 3. Point factory DNS
#    spark.lan  →  <server LAN IP>   (edit deploy/.env ONPREM_PUBLIC_URL if using another name)

# 4. Open from any factory PC/tablet
#    http://spark.lan
```

First login with `--seed`: **admin / changeme** — change the password immediately under Profile.

## Configuration

Copy and edit environment variables:

```bash
cp deploy/.env.onprem.example deploy/.env
nano deploy/.env
```

Key settings:

| Variable | Description |
|----------|-------------|
| `ONPREM_PUBLIC_URL` | URL workers use in browser, e.g. `http://spark.lan` |
| `JWT_SECRET` | Must be strong; auto-generated by setup script |
| `LLM_PROFILE` | `rag_th` (7B, better Thai) or `demo` (3B, less RAM) |
| `CELERY_CONCURRENCY` | Ingest worker parallelism (default 2; use 4 on 8-core servers) |
| `ONPREM_API_WORKERS` | Uvicorn workers (**default 2** in on-prem kit; use ≥2 in production) |
| `SPARK_DB_STREAM_POOL_SIZE` | Dedicated pool for long-lived SSE/chat streams (default **10**). Size as `workers × stream_pool ≥ peak concurrent chats`. |
| `TRUSTED_PROXIES` | Comma-separated CIDRs for nginx/LB (e.g. `172.16.0.0/12`) — required for correct client IP behind reverse proxy |
| `AUDIT_EXPORT_HMAC_SECRET` | HMAC for signed audit exports (production lock v2) |
| `REDIS_URL` | **Required** in production — API refuses startup if Redis is unreachable |

### Dual admission + nginx SSE

The API separates **transactional HTTP** and **long-lived SSE** admission planes (independent concurrency caps). Nginx must:

- Set `proxy_buffering off` on `/api/` (already in `deploy/nginx/conf.d/spark.conf`) so chat tokens flush immediately.
- Configure `set_real_ip_from` to match `TRUSTED_PROXIES` on the API container.
- Run **≥2** API workers (`ONPREM_API_WORKERS`) with Redis so stream tickets are single-use across workers.

### Readiness probes (`/readyz`)

| Query | Use case |
|-------|----------|
| `GET /readyz?lite=1` | **Docker/K8s healthcheck** — Postgres `SELECT 1` + Redis PING only (fast) |
| `GET /readyz` | Full dependency matrix, **cached 30s** in-process |
| `GET /readyz?deep=1` | Full matrix, bypass cache (post-deploy smoke) |

On-prem `docker-compose.onprem.yml` uses `?lite=1` for the API healthcheck so frequent ticks do not hammer Qdrant/Ollama.

Rebuild web after changing `ONPREM_PUBLIC_URL`:

```bash
docker compose -f deploy/docker-compose.onprem.yml --env-file deploy/.env --project-directory deploy build web
docker compose -f deploy/docker-compose.onprem.yml --env-file deploy/.env --project-directory deploy up -d web nginx
```

Browser API calls use **same-origin** paths (`/api/v1/...`) through nginx — no CORS issues on the LAN.

## SSE / chat streaming

Chat answers stream via `POST /api/v1/chat/{session}/ask` with `text/event-stream`. Nginx is configured with:

- `proxy_buffering off`
- `proxy_cache off`
- `gzip off` on `/api/`
- 24-hour read timeout

This also covers:

- `GET /api/v1/alerts/stream` (operator alerts)
- `GET /api/v1/ingest/jobs/{id}/stream` (upload progress)

If streaming breaks after adding an external load balancer, apply the same no-buffer settings there.

## Performance tuning (included in compose)

These settings reflect bottlenecks found in the Spark codebase:

| Tuning | Reason |
|--------|--------|
| **Celery `--max-tasks-per-child=50`** | Ingest tasks load sentence-transformers + OCR; recycles worker memory after heavy jobs |
| **Celery `shm_size: 2gb`** | PyTorch / cross-encoder reranker uses shared memory during embedding |
| **`worker_prefetch_multiplier=1`** (in code) | Long ingest jobs — prevents one worker hoarding the queue |
| **Redis `maxmemory 512mb` + LRU** | Auth token-version cache; bounds Redis growth on 24/7 factory servers |
| **Qdrant int8 quantization + on-disk payload** | Matches `docker-compose.prod.yml` — lowers RAM for large document corpora |
| **Ollama `OLLAMA_NUM_PARALLEL=2`** | Allows chat + background judge calls without serializing |
| **Postgres `shared_buffers=256MB`** | Stable baseline for mixed OLTP + analytics queries |

On a **32 GB / 8-core** server, try in `deploy/.env`:

```env
CELERY_CONCURRENCY=4
ONPREM_API_WORKERS=2
OLLAMA_MEMORY_LIMIT=20g
```

## Backup & restore

**Critical data:**

```bash
# Application files (uploads, feedback photos)
tar -czf spark-data-backup.tar.gz -C deploy data/

# Database
docker compose -f deploy/docker-compose.onprem.yml --env-file deploy/.env \
  --project-directory deploy exec -T postgres \
  pg_dump -U spark spark_db > spark_db_backup.sql

# Named volumes (optional full snapshot)
docker run --rm -v spark_onprem_qdrant_data:/data -v $(pwd):/backup alpine \
  tar -czf /backup/qdrant_backup.tar.gz -C /data .
```

Restore Postgres: pipe `spark_db_backup.sql` into `psql` inside the postgres container.

## Troubleshooting

| Symptom | Fix |
|---------|-----|
| Chat shows no streaming / long pause then full answer | Confirm nginx config has `proxy_buffering off` on `/api/`; restart nginx |
| `502 Bad Gateway` on startup | API still booting — wait 60s; check `$ENV logs api` |
| Ollama OOM | Lower to `LLM_PROFILE=demo` or reduce `OLLAMA_MEMORY_LIMIT` |
| Ingest jobs stuck | Check `$ENV logs celery_worker`; ensure disk space in `deploy/data/` |
| Login works on server but not tablets | DNS — verify `spark.lan` resolves to server IP from client subnet |
| Google OAuth fails | Set `GOOGLE_OAUTH_CALLBACK_URL=http://spark.lan/api/v1/auth/google/callback` in Google Console |

## Security checklist (production)

- [ ] Change all `CHANGE_ME` secrets (setup script auto-generates on first run)
- [ ] Set strong admin password; review super-admin users after migration 0035
- [ ] Restrict firewall to factory subnet only (port 80/443)
- [ ] Do **not** expose postgres/redis/qdrant ports to WAN (compose keeps them internal)
- [ ] Disable Google OAuth if using password-only intranet (leave client ID blank)
- [ ] Schedule backups of `deploy/data/` and postgres dumps
